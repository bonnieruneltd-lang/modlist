# -----------------------------------------------------------------------------
#  6. WHY EACH RECORD IS HERE  (mechanism, then the caveat that matters)
#     P1.x entries are shipped (rev 4) - their notes are kept because they are
#     the reason those jars are in the pack; P2.x entries are still proposals.
# -----------------------------------------------------------------------------
#  P1.1  notenoughrecipebook  (BOTH)
#        1.20.1 syncs every unlocked recipe name to the client on join and keeps
#        the list in the player file. In a pack with 30+ mods that blob is the
#        single largest per-player packet burst. NERB removes the feature
#        instead of hiding the button, so join time and player-data size drop.
#        Caveat: the recipe book UI is gone for good - JEI stays. The jar is
#        21 KB but needs ShatterLib/OctoLib, which in turn needs
#        architectury-api (already a BOTH record in category 3).
#
#  P1.2  ksyxis  (SERVER)
#        On 1.8-1.20.4 Ksyxis removes the permanently loaded 21x21 spawn-chunk
#        area - its own table rates 1.20.1 "Extreme". That is RAM and tick work
#        the server pays for from boot to shutdown on a world that is mostly
#        empty at spawn. Caveat: farms or contraptions that rely on spawn
#        chunks stop running; deleting the jar restores them.
#
#  P1.3  async-locator  (SERVER)
#        Moves vanilla structure search off the tick thread for /locate, villager
#        explorer-map trades, dolphin treasure and chest exploration maps. One
#        /locate in a Tectonic-shaped world can stall a tick for seconds; this
#        turns that into a background task. Caveat: it only covers vanilla
#        feature lookups - modded /locate implementations have to opt in - and
#        the 1.20.1 build is from 2023 and still the newest one.
#
#  P1.4  structure-layout-optimizer  (SERVER)
#        Vanilla stores jigsaw piece bounds in a VoxelShape and tests every new
#        piece against all of them. SLO swaps that for a BoxOctree so only
#        nearby pieces are compared, and the author's stated goal is zero visual
#        change. It is the structure-generation counterpart to Starlight and
#        Noisium, which already cover lighting and biome noise, and it matters
#        here because Tectonic makes the overworld considerably heavier to
#        generate than vanilla. Caveat: new-ish project, no config beyond its
#        Resourceful Config file.
#
#  P1.5  cull-leaves  (CLIENT)
#        Drops leaf-block faces that cannot be seen - the OptiFine "Smart
#        Leaves" feature reimplemented for the Sodium/Embeddium renderer. In a
#        forest/jungle this is the biggest cheap FPS win left on the client.
#        Caveat: needs MidnightLib; pairs with a Better Leaves style resource
#        pack, which the pack does not ship.
#
#  P1.6  rubidium-extra  (CLIENT)
#        Sodium Extra ported to Embeddium: per-category particle, entity, fog
#        and animation toggles plus a few renderer bugfixes Embeddium itself does
#        not expose. This is the cheapest FPS that does not need new hardware -
#        and the only way to cut, say, "all block-break particles" without
#        installing a second particle mod. Caveat: it is an unofficial fork, so
#        keep it pinned to the recorded build and re-test after Embeddium bumps.
#
#  P1.7  kerria-opt  (CLIENT)
#        Vanilla re-uploads every frame of every animated texture through
#        glTexSubImage2D, i.e. CPU to GPU traffic per frame plus a possible
#        pipeline stall. Kerria caches a non-interpolated animation once and
#        uses PBO-style uploads afterwards; it scales with the number of
#        animated textures in view (water, lava, fire, modded tanks). Caveat:
#        it hooks Embeddium's video settings screen, so it is client-tier only
#        and should be re-tested whenever Embeddium is updated.
#
#  P1.8  obe  (CLIENT)
#        Optimized Block Entities bakes static block entities (chests, signs,
#        banners, spawners) into the terrain mesh, which is the batched path
#        Embeddium already optimises, and falls back to the vanilla renderer for
#        animated ones. Dense bases are where this shows. Caveat: newest project
#        in P1 (2026) and it touches terrain batching, i.e. exactly what shaders
#        hook - test all three shader tiers and drop the record from the H tier
#        first if anything glitches.
#
#  P1.9  rrls  (CLIENT)
#        Removes the blocking "Reloading resources" screen when a resource pack
#        or shader pack is switched. Pure UX: zero TPS, but it is the difference
#        between a 20 s freeze and none on a pack this size.

#  P2.1  fastsuite  /  P2.2 fastworkbench  /  P2.3 fastfurnace  (BOTH)
#        All three by Shadows_of_Fire, all three need Placebo. Vanilla matches
#        recipes by walking a list; FastSuite caches the match per inventory,
#        FastWorkbench caches the crafting-grid result (shift-click spam is the
#        worst case) and FastFurnace caches furnace/smoker/blast-furnace
#        lookups. Caveat: they cache, so anything that rewrites recipes at
#        runtime (CraftTweaker, KubeJS) can show stale results - this pack has
#        neither, and JEI is unaffected.
#
#  P2.4  lmd  (SERVER)
#        Vanilla never despawns a mob that picked up or equipped an item, so
#        every zombie that grabs a sword is permanent. LMD restores normal
#        despawning while keeping the drops, with a config exclusion list for
#        pets/named mobs. Caveat: gameplay change - vote on it before shipping.
#
#  P2.5  railoptimization  (SERVER)
#        Powered/activator rail state changes are re-computed along the whole
#        network in vanilla; this makes them up to ~20x faster by the author's
#        benchmark table. Caveat: only measurable if players build rail lines -
#        this pack has Small Ships and Minecarts, not Create-scale rail spam.
#
#  P2.6  renderscale  (CLIENT, L/M)
#        Renders the world at 0.5-1x of the window resolution and upscales,
#        leaving the UI sharp (fork of ResolutionControl++). This is the correct
#        answer for a 1080p + shaders GPU that sits at 40 FPS, where dropping
#        render distance costs more visually. Caveat: the 1.20.1 build is a beta
#        and it fights shader packs that own the framebuffer - test with Oculus
#        enabled and disabled.

#  7. CONFIG AND JVM WORK  (the part that beats every jar on this list)
# -----------------------------------------------------------------------------
#  7.1  SERVER JVM FLAGS  (Aikar's, G1GC, Java 17 - Forge 47 does not run 21)
#       -Xms8G -Xmx8G -XX:+UseG1GC -XX:+ParallelRefProcEnabled
#       -XX:MaxGCPauseMillis=200 -XX:+UnlockExperimentalVMOptions
#       -XX:+DisableExplicitGC -XX:+AlwaysPreTouch -XX:G1NewSizePercent=30
#       -XX:G1MaxNewSizePercent=40 -XX:G1HeapRegionSize=8M
#       -XX:G1ReservePercent=20 -XX:G1HeapWastePercent=5
#       -XX:G1MixedGCCountTarget=4 -XX:InitiatingHeapOccupancyPercent=15
#       -XX:G1MixedGCLiveThresholdPercent=90
#       -XX:G1RSetUpdatingPauseTimePercent=5 -XX:SurvivorRatio=32
#       -XX:+PerfDisableSharedMem -XX:MaxTenuringThreshold=1
#       Rules: -Xms and -Xmx identical; 6-10 GB for this pack size; region size
#       8M for heaps up to ~16 GB; drop to a plain -XX:+UseG1GC set if the host
#       already passes its own GC flags. Flag set cross-checked against
#       crafty.gg/tools/server-flags and berrybyte.net/wiki (Aikar's flags).
#
#  7.2  SERVER.PROPERTIES  (the ones that actually move tick time)
#       sync-chunk-writes=false      chunk IO off the main thread; Paper forces
#                                    it, Forge has to be told. Re-test against
#                                    Shinoyuki-BetterAutoSave.
#       view-distance=6..8           server-side render distance; 10 is the
#                                    default and is too much for 30+ mods
#       simulation-distance=4..6     entity/AI radius - the single biggest
#                                    entity-tick lever after Mobtimizations
#       entity-broadcast-range-percentage=75   fewer entity packets
#       network-compression-threshold  256 default; 512 on a CPU-bound box with
#                                    good upstream; -1 ONLY for a proxy on the
#                                    same host
#       max-tick-time=60000 default; -1 disables the watchdog - only do that if
#                                    the host restarts a frozen process itself
#       max-chained-neighbor-updates=10000   bounds redstone cascades (changes
#                                    behaviour, so it is a decision, not a fix)
#       use-native-transport=true     Linux hosts, on by default
#
#  7.3  CONFIGS OF MODS ALREADY IN THE PACK  (zero download)
#       ModernFix      leave every patch on; if one mod misbehaves, disable the
#                      single patch in its config instead of dropping the mod
#       FerriteCore    memory only, defaults are the right defaults
#       Krypton Reno   networking, no user config worth touching
#       ServerCore     per-patch toggles - bisect by turning one patch off
#       Embeddium      render distance, chunk builder threads, entity distance,
#                      cloud/weather quality: tune these before adding a jar
#       Entity Culling block-entity culling + async culling on; it is the most
#                      aggressive entity culler and stacks with Embeddium
#       ImmediatelyFast HUD batching on; disable only the batching a mod breaks
#       Dynamic FPS    set the unfocused cap to 5-10 FPS - that is free CPU on
#                      every alt-tabbed client
#       Spark          /spark tps, /spark health, /spark profiler start
#                      --timeout 60: measure, do not guess
#       Chunky         pre-generate before opening the doors: /chunky radius
#                      2000, /chunky start, /chunky pause when players are on.
#                      A pregenerated world removes the biggest source of tick
#                      spikes and is what makes Starlight + Noisium pay off
#
#  7.4  HYGIENE
#       * no OptiFine on any tier - Embeddium + Oculus replace it and the pack
#         is built around that
#       * client 6-8 GB with -Xms == -Xmx; the launcher default of 2 GB will
#         stutter with three shader packs installed no matter what you add
#       * one renderer per side: Embeddium today, Xenon only if you swap it out
#       * keep every jar pinned (MRPACK-MANIFEST.txt already does this)
#
#  7.5  MEASURING, so the next revision is not guesswork
#       Change one thing per run, stand in the same spot at the same time of
#       day, log F3 (client) and /spark tps + a 60 s profiler (server) before
#       and after. Numbers on a project page are the author's hardware, not this
#       pack's; the only figure that counts is the one measured here.
