B. FINDINGS THAT CHANGE A PACK
---------------------------------------------------------------------------

  B1  BLOCKER  Lithostitched is missing from the server mod list
      Tectonic is server=required (Modrinth: client=optional, server=required)
      and depends on Lithostitched (Modrinth: client=unsupported,
      server=required). Lithostitched appears only in the four client tiers
      (packs=N,L,M,H) and not in source/modlist-server.txt, so the dedicated
      server would load Tectonic without its library.
      Fix: add `mod|modrinth|lithostitched||Lithostitched` to the server list and
      set env.client=unsupported for it in the .mrpack manifests.

  B2  HIGH  Mobtimizations is required on the client but only ships on the server
      Modrinth reports client_side=required, server_side=required. It is in the
      server list only (packs=S), so RUNE clients connect without a mod the
      server expects on both sides.
      Fix: add it to the four client tiers, or drop it server-side.

  B3  HIGH  BadOptimizations is client-only but sits in the server mod list
      Modrinth: client=required, server=unsupported. Shipping it to the server
      is at best a dead jar and at worst a mixin crash on a headless server.
      Fix: remove `mod|modrinth|badoptimizations` from the server list (it is
      correctly present in all four client tiers).

  B4  HIGH  RUNE NOTES contradict the server list about Krypton Reforged
      source/rune-modpack-filelist.txt says "Krypton Reforged and More Culling
      are CurseForge-only for Forge 1.20.1 and were omitted (no Modrinth Forge
      1.20.1 build exists)", but the server list ships Krypton Reforged
      (curseforge 549394, Forge 1.20.1). Either the note is stale or the server
      list is wrong. More Culling is genuinely absent from both lists.

  B5  MEDIUM  Krypton Reforged advertises a required client install
      CurseForge description: "Krypton optimizes the Minecraft networking stack,
      meaning it mostly improves server performance with lots of clients, but is
      also required on the client." Modrinth's Krypton is optional/optional.
      Filed as BOTH (client=optional, server=optional); if the Forge port really
      needs the client half, clients will log handshake/channel warnings.
      Needs a smoke test with a client that does not have Krypton Reforged.

  B6  MEDIUM  env fields in the .mrpack manifests do not match mod capability
      12 RUNE entries declare client=required where Modrinth reports
      client=optional: Simple Voice Chat, Tectonic, AppleSkin, Balm, Cloth
      Config, Jade, JEI, MezzConfig, FerriteCore, Memory Leak Fix, ModernFix,
      Starlight. Inside a client .mrpack "client=required" is a defensible
      packaging decision, so those are INFO-level. The two that are actually
      wrong are Lithostitched (client unsupported) and Tectonic (client
      optional, i.e. a vanilla client can join a Tectonic server).
      The claim "All files are client-installable (env.client = required)" in the
      RUNE header is therefore not true for Lithostitched.

  B7  MEDIUM  Server list omits Cloth Config and MezzConfig
      Both appear only in the client tiers. Both are client=optional /
      server=optional, so nothing is broken today, but any server-side mod that
      binds to them would silently lose its config. Worth a dependency pass
      together with B1.

  B8  LOW  Simple Voice Chat is server=optional in the RUNE manifest
      Voice chat does not work unless the mod is on the server, and the server
      list does ship it, so the server pack is right. Only the manifest flag is
      misleading (server should be listed as required for this pack).

  B9  LOW  UltimateAntiSeedCracker is a datapack, not a mod
      Filed as `datapack|SERVER`. It belongs in <world>/datapacks/, not in mods/.
      `kind` is recorded so the packaging step cannot put it in mods/ by mistake.

G. POST-AUDIT ADDITIONS  (requested 2026-11-09, after the lists were delivered)
---------------------------------------------------------------------------
  Request: vein mining, "faster minecarts and horses", and "a mod to backport
  everything from future versions". Every project below was resolved through
  the Modrinth project/version API or the CurseForge project record and has a
  Forge 1.20.1 build. All four new records are in packs S,N,L,M,H.

  G1  Vein mining - NO new record needed
      ChainVein (modrinth QAajHeqM, 4.4.0) is already in the pack (category 1,
      BOTH, packs S,N,L,M,H) and IS the pack's vein-mining implementation
      ("Mine connected blocks and ores"). Adding a second vein miner
      (VeinMiner OhduvhIc, Vein Mining bRAPbNyF, QuickMine YyIGSTNM) would
      handle the same block-break event twice and risk duplicated drops and
      clashing keybinds, so the request is met by the existing record.

  G2  Vanilla Backport  ->  01-content-and-gameplay.txt, BOTH, 1.2.2
      modrinth 6xwxDTgf, jar VanillaBackport-forge-1.20.1-1.2.2.jar,
      client_side=required, server_side=required (Modrinth project API).
      Backports modern vanilla content (mobs, blocks, items) to 1.20.1 - the
      "everything from future versions" request.
      It declares one REQUIRED dependency: Platform (G3).

  G3  Platform  ->  03-utilities-qol-libraries.txt, BOTH, 1.4.2
      modrinth i6fiqm5y, jar Platform-forge-1.20.1-1.4.2.jar,
      client_side=optional, server_side=optional (Modrinth project API).
      Author metadata says optional, but it is a hard dependency of Vanilla
      Backport, so treat it as required wherever G2 is installed. Adding it
      with G2 avoids repeating B1 (Tectonic shipped without Lithostitched).
      Name trap: slug `platform` is ItsBlackGear's cross-platform library.

  G4  Darceno's Minecarts  ->  01-content-and-gameplay.txt, SERVER, 1.3+mod
      modrinth RZw0JtqY, jar darcenos-minecarts-1.3.jar,
      client_side=optional, server_side=required (Modrinth project API).
      Ridden minecarts and minecarts-with-chest move far faster than vanilla;
      the mod also chunk-loads carts that are travelling. The speed change is
      server-authoritative, so a vanilla client still rides the fast cart -
      which is why the record is filed SERVER with client=optional.
      Caveat: pin the `1.3+mod` build exactly, NOT the `slower.1.3+mod` variant.
      Lighter CurseForge alternative if elytra-speed carts are too much:
      Faster Minecarts Forgified, curseforge 1398875 (twice vanilla speed).

  G5  Better Horses and Donkeys  ->  01-content-and-gameplay.txt, SERVER, 1.1
      curseforge 968867 (slug faster-horses-donkeys-and-mules), artefact
      betterhorses-1.1.jar (file 8551421, tagged 1.20.1 / Forge / Server).
      "Configurable improvement of Horse speed, jump height, and more!" -
      horses, mules, donkeys and modded saddled creatures. Not published on
      Modrinth, so client/server is read from the CurseForge file tags and
      description: client=optional, server=required (the changes are entity
      attribute changes, i.e. server-side).
      Modrinth alternatives considered and rejected: Horseman qIv5FhAA (QOL,
      no speed change) and Icy's Better Horses XlUm5I57 (full overhaul, needs
      GeckoLib + Patchouli, i.e. two more libraries).

  G6  Smoke test still owed
      Vanilla Backport adds registry content and worldgen. Boot a copied world
      once with Vanilla Backport + Tectonic 3.0.17 + Lithostitched before
      release, and watch the log for registry id clashes with Waystones /
